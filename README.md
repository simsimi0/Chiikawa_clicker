# 치이카와 클리커 · 로컬 게스트 버전

## 최신 조작·이미지 업데이트

- 기본 캐릭터 8종을 각각 독립된 SVG 표시 파일(`assets/characters/*_0.svg`)로 분리했습니다. 공식 PNG를 그대로 내장하고 명시적인 클리핑 경계를 적용해 옆 캐릭터가 보이지 않습니다. 현재 표시 크기에 충분한 원본 픽셀을 유지하므로 AI로 다시 그리거나 해상도를 임의로 부풀리지 않았습니다. `node scripts/build-character-views.cjs`로 재생성할 수 있습니다.
- 메인 화면의 **캐릭터 바꾸기**에서 한 번 구매한 기본/후드 모습을 선택할 수 있습니다. 옷만 사고 아직 해당 캐릭터를 구매하지 않았다면 선택할 수 없습니다. 선택은 저장·새로고침·환생 후 유지됩니다. 기존 JSON 저장도 읽을 수 있습니다.
- 클릭 획득량, 주요 재화 표시, 상점·강화 가격과 오프라인 획득량에 초록색 보수 주머니 아이콘을 사용합니다. 공식 굿즈의 ‘報酬袋’를 참고한 게임용 단순 아이콘이며, 특정 화폐 단위가 공식 명칭이라고 주장하지 않습니다. 참고: https://chiikawamarket.jp/products/4582662913554
- 클릭 모션은 통통 뛰기/좌우 흔들기/살짝 커지기의 3종입니다. 이미지 비율을 유지하며 움직입니다. 설정의 애니메이션 끄기와 운영체제의 동작 줄이기를 따릅니다.
- 반응음은 캐릭터별 4종, 총 32개 WAV입니다. **실제 애니메이션 음성이 아닌 임시 합성 보컬 효과음**입니다. 원작 성우의 말투나 소리를 재현하지 않습니다. 기본은 꺼져 있으며 메인 화면에서 켜거나 설정에서 음량을 바꿀 수 있습니다.
- 설정에서 직접 준비한 음성을 캐릭터별 1~4개 선택해 현재 실행 동안 교체할 수 있습니다. 화자와 내용을 확정한 원작 캐릭터 클릭음은 아직 기본값에 수록하지 않았습니다. 아래의 유튜브 후보를 확인하거나 직접 준비한 음성 파일로 교체할 수 있습니다. 파일 설명은 `assets/sounds/README.md`에 있습니다.
- 사용자가 제공한 AniBox 재생목록의 원본 오디오에서 **후보 12개**를 추출했습니다. `audio-review.html`에서 들을 수 있습니다. 화자/소리 청취 검증 전이므로 자동 적용하지 않았습니다. 확인한 파일을 설정에서 선택할 수 있습니다. 출처·타임스탬프·확인 상태는 `AUDIO-SOURCES.md`와 후보 manifest에 있습니다.
- 자동 테스트 20개와 DOM 모의 실행으로 구매→선택→저장→재실행→환생 경로, 전체 메뉴, 재화 파티클, 모션 클래스 및 음원 재생 요청을 확인했습니다. 실제 브라우저 화면·음성 청취 확인과는 구분합니다.

## 실행

`index.html`을 Chrome 또는 Edge로 열면 됩니다. `start.cmd`를 더블클릭해도 됩니다. 설치·인터넷·Firebase 없이 작동합니다.

항상 같은 브라우저와 같은 파일 경로에서 실행하세요. 파일을 옮기거나 다른 브라우저로 바꾸면 저장 영역이 달라질 수 있으므로 먼저 **설정 → JSON 내보내기**로 백업하세요. 브라우저가 파일 주소의 저장을 차단한다면 Node.js 환경에서 다음 명령을 사용하세요.

```text
node server.cjs
```

이후 `http://127.0.0.1:4173`으로 접속하세요. 파일 실행과 서버 실행의 저장 공간은 서로 다릅니다. JSON 가져오기로 옮길 수 있습니다. 서버를 멈추려면 Ctrl+C를 누릅니다.

## 이번 버전의 범위

- 클릭·실시간 자동 생산·상점·1/10/100/최대 구매
- **옷 구매 → 해당 옷의 캐릭터 개별 구매**의 두 단계 상점
- 8명 × 기본/후드/의상 02/의상 03 = 32개 생산 항목
- 보유 수량별 2배 강화, 항목별 강화, 전체 및 클릭 강화
- 옷장 수집 보너스·세트 보너스·반복 의뢰·업적 및 달성 시각
- 환생 포인트·6종 영구 강화·오프라인 보수
- 5초 자동 저장·주요 이벤트 저장·이전 저장 복구·JSON 가져오기/내보내기
- 한 탭 진행 제한·애니메이션 끄기·개별 클릭 효과음·배경음악 파일 선택·3종 화면 테마
- 공식 공개 기본 원본 8종과 **후드를 입은 AI 팬 편집 8종** (기존 후드 단품 SVG 시안도 보관)

Google 로그인과 Firebase 클라우드 저장은 이번 1·2단계 범위에 포함되지 않습니다. 현재의 저장은 이 브라우저에만 있습니다.

## 옷과 캐릭터 구매 규칙

1. 기본 모습은 처음부터 구매할 수 있습니다. 치이카와 기본 모습은 도감에 무료 등록되지만 자동 생산 수량은 0에서 시작합니다. 상점에서 기본 치이카와를 구매하면 자동 생산에 참여하는 수량이 생깁니다.
2. 후드는 **2,500 코인**, 의상 02는 **25,000,000 코인**, 의상 03은 **250,000,000,000 코인**으로 구매합니다. 누적 생산량 달성만으로 자동 해금되지 않습니다.
3. 옷을 사면 해당 옷을 입은 8명 각각의 구매 자격이 열립니다. 캐릭터가 자동 지급되거나 자동 생산이 생기지는 않습니다.
4. 후드 치이카와, 후드 하치와레 등 원하는 캐릭터를 다시 코인으로 구매합니다. 각 항목은 독립적인 가격·수량·생산량을 갖습니다.
5. **옷 구매는 환생 후에도 유지**됩니다. 캐릭터 생산 수량은 초기화되며 도감 및 누적 구매 기록은 유지됩니다.
6. 후드와 나머지 옷의 공통 이름은 설정에서 수정할 수 있습니다. 의상 02·03은 사용자 원본에 맞춰 이름을 정할 확장 슬롯입니다. 캐릭터별 표시 이름도 따로 수정할 수 있습니다.

## 장기 성장

- 같은 구매 항목을 10/25/50/100/150/200/300/500개 모을 때마다 그 항목 생산량이 2배로 증가합니다.
- 항목별 일반 강화는 다음 레벨마다 10×(레벨+1)개 보유가 필요하며 생산량이 2배가 됩니다. 최대 20레벨입니다.
- 클릭 강화와 전체 강화도 최대 20레벨입니다. 클릭 강화 5레벨부터 클릭 수익에 CPS의 일부가 더해집니다.
- 처음 구매한 모습마다 컬렉션 보너스 +1%p, 같은 옷 단계의 8종을 모두 구매하면 추가 +10%p가 생깁니다. 무료 도감 등록만으로는 보너스가 생기지 않습니다. 수집 보너스는 환생 후에도 유지됩니다.
- 의뢰는 누적 생산/클릭/구매 기록을 기준으로 진행됩니다. 보상은 자동 수령되지 않으므로 직접 누르세요. 각 의뢰는 100단계입니다.
- 도장 보너스: `min(100%, sqrt(도장 수) × 2%)`. 업적 보너스: 업적 1개마다 +0.5%p.
- 생산량은 수량 배율 × 항목 강화 × 영구 자동 강화 × 전체 강화 × 컬렉션 × 도장 × 업적 보너스를 곱합니다.
- 옷을 먼저 열지, 기존 친구를 더 모을지 선택하는 것이 핵심입니다. 가격은 모두 `core.js`의 `PEOPLE`, `TIERS` 등에서 수정할 수 있습니다. 플레이 시간과 장기 경제 밸런스는 초안이며 실플레이 피드백으로 조정해야 합니다.

## 환생

`획득 예정 = max(0, min(1e12, floor(sqrt(전체 누적 생산 / 1,000,000))) - 역대 획득 포인트)`

획득 예정 포인트가 1 이상일 때만 환생할 수 있습니다. 영구 강화에 사용한 포인트는 역대 획득량에서 빠지지 않습니다. 다음 포인트 목표는 `(역대 획득 포인트 + 1)^2 × 1,000,000`입니다.

초기화: 코인, 생산 수량, 항목/클릭/전체 일반 강화, 회차 생산량.

유지: 옷 구매, 수집·누적 구매, 전체 생산량, 클릭·플레이 기록, 환생 횟수, 사용 가능/역대 포인트, 영구 강화, 업적, 의뢰·도장, 설정. 등록한 이미지와 이름도 별도 저장되어 유지됩니다.

## 원본 캐릭터 이미지 등록

방법 A: 게임 설정 → 항목 선택 → 원본 이미지 등록. 원본 파일을 가공하지 않고 Data URL로 보관합니다. PNG/JPG/WebP, 파일당 700KB 이하, 전체 등록 정보 약 2.8MB 문자열 한도입니다. 브라우저 공간이 부족하면 저장하지 않고 안내합니다. 이름은 항목별 최대 40자입니다.

방법 B: 큰 원본은 아래 파일명을 사용해 `assets/characters/`에 넣으세요. 예: `hachiware_1.png`는 후드 하치와레입니다. `0`은 기본, `1`은 후드, `2`는 의상 02, `3`은 의상 03입니다.

| 캐릭터 | 파일명 형식 |
|---|---|
| 치이카와 | chiikawa_0.png ~ chiikawa_3.png |
| 하치와레 | hachiware_0.png ~ hachiware_3.png |
| 우사기 | usagi_0.png ~ usagi_3.png |
| 쿠리만쥬 | kurimanju_0.png ~ kurimanju_3.png |
| 시사 | shisa_0.png ~ shisa_3.png |
| 모몽가 | momonga_0.png ~ momonga_3.png |
| 후루혼야 | furuhonya_0.png ~ furuhonya_3.png |
| 라코 | rakko_0.png ~ rakko_3.png |

설정에서 등록한 이미지가 폴더의 파일보다 우선합니다. 설정의 ‘이 항목 등록 해제’를 누르면 폴더 이미지로 돌아갑니다. 등록한 이미지 비율을 유지하며 표시합니다. 기본 모습은 공식 원본, 후드 모습은 AI 팬 편집입니다.

게임 JSON에는 이미지/의상 이름 등록 정보와 음악이 들어 있지 않습니다. 폴더의 원본 파일은 직접 보관하고, 설정에서 등록한 이미지는 원본을 따로 보관하세요. 음악은 현재 실행 중에만 선택한 파일을 재생합니다.

## 저장·오프라인·복구

- localStorage에 현재 저장과 이전 정상 저장을 보관합니다. 5초 간격, 구매·강화·환생 등 주요 행동, 탭 숨김 시 저장합니다. 갑작스러운 브라우저/기기 종료 시 마지막 저장 이후의 진행은 손실될 수 있습니다.
- 현재 저장이 손상되면 이전 정상 저장으로 복구합니다. 둘 다 손상된 경우 안내 후 새 게임이 시작됩니다. 별도 JSON 백업을 가져올 수 있습니다.
- 원본 저장의 마지막 계산 시각부터 오프라인 보수를 계산하고 지급 시각을 즉시 저장합니다. 탭을 숨긴 동안에도 같은 규칙을 적용합니다. 기본 50% 효율·최대 8시간이며 영구 강화로 100%·24시간까지 늘어납니다.
- JSON 가져오기/이전 저장 수동 복구는 원본의 오래된 시각을 이용한 추가 오프라인 보상을 지급하지 않습니다.
- 같은 브라우저·같은 주소에서 탭 하나만 진행합니다. 다른 탭을 닫은 후 최대 15초 뒤 새로고침해 이어갈 수 있습니다. 여러 기기/서로 다른 브라우저 간 제어는 Firebase 단계의 별도 과제입니다.
- 기기 시각 조작과 수동 JSON 편집을 완전히 차단하는 서버 검증은 없습니다. JSON의 구조·수치 범위·환생 포인트 합계 등 무결성만 확인합니다.
- 지원 수치는 1e150까지이며 JavaScript Number를 사용하므로 큰 수의 작은 차이는 근삿값입니다. 항목당 최대 보유 5,000개, 환생 포인트 누적 1e12 한도입니다.

## 파일과 검증

`core.js`: 상태·가격·경제·옷 구매·강화·환생·업적·의뢰·오프라인·스키마 검증.

`save.js`: 로컬 저장·정상 백업·탭 잠금·이미지 등록 정보.

`app.js`: 화면·상호작용·효과음·설정·파일 가져오기/내보내기.

`style.css`: 반응형 화면. 외부 폰트나 외부 라이브러리 의존성 없음.

다음 명령으로 계산/저장 검증을 실행합니다.

```text
node --test tests.cjs
```

기본 캐릭터의 공식 공개 원본과 후드 팬 편집 이미지 8종을 포함합니다. 음악은 포함하지 않습니다. 게임 하단에 비공식 팬 게임 안내를 표시합니다.
